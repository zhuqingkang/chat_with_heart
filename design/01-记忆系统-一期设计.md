## 1. 记忆金字塔（目录即架构）

五层结构，越往上抽象程度越高、细节越少、更新频率越低：

| 层 | 文件 | 内容 | 更新频率 |
|---|---|---|---|
| L0 人格 | memory/system.md | 用户定义的人格设置（agent 的"宪法"） | 极低，手动 |
| L1 全史 | memory/years.md | 跨年抽象：用户是谁、关系演变史 | 每月检查 |
| L2 年度 | memory/<year>/year.md | 该年主线、情绪趋势 | 月末滚动 |
| L3 月度 | memory/<year>/<N>month/month.md | 当月主题、情绪曲线 | 每日滚动 |
| L4 日志 | memory/<year>/<N>month/<yyyy_mm_dd>.md | 单日对话摘要 + 情感标注 | 每次对话 |

目录结构即架构：不需要额外的元数据层或索引层，
文件路径本身就是"这条记忆属于哪一层、哪个时间"的答案。

## 2. 情感状态模型（核心抽象）

每条记忆条目 = 事件描述 + 情感元数据。采用 PAD 情感模型的简化二维：

| 字段 | 范围 | 含义 |
|---|---|---|
| mood_valence | -1.0 ~ +1.0 | 愉快度：负面 ← → 正面 |
| mood_arousal | 0.0 ~ 1.0 | 唤醒度：平静 ← → 激动 |
| affinity | 0 ~ 100 | 累计好感度 |
| affinity_delta | -10 ~ +10 | 本次事件引起的变化 |
| persona_note | 文本 | 当时的性格表现（一句话） |
| mood_label | 离散标签 | 平静/开心/烦躁/兴奋/疲惫… |

约定：
- 情感状态由 LLM 从对话**推断**，是叙事层的模拟，不是真实主观体验；
- affinity **只累加、不衰减**（2026-10-29 用户要求移除每日 10% 衰减），
  单事件 |delta| 上限 10 用于防刷分；
- valence/arousal 二维可定位大多数日常情绪：
  兴奋 = 高唤醒高愉快，烦躁 = 高唤醒低愉快，平静 = 低唤醒，抑郁 = 低唤醒低愉快。

**当前状态另有承载物**：`memory/state.json` 存"记忆的现在时"
（affinity / valence / arousal / mood_label / updated_at），
与 L4 日志的"过去时"分离。日志条目追加写入，状态是单点覆盖。

## 3. 日志条目格式（L4 文件的原子单位）

```markdown
## HH:MM <短标题>
- 事件：<用户做了什么/聊了什么，一两句>
- 心情：<标签>（valence ±x.x，arousal x.x）
- 性格表现：<一句话>
- 好感度：±N → <累计值>
```

文件头示例：

```markdown
# 2026-10-29 对话记忆

> 由 nanocode 自动蒸馏写入。格式规范见本文件 §3。
```

## 4. 写路径：记忆蒸馏管线

```
对话结束（/q 或 /c）
  → distill(day)：LLM 总结本次会话 → 按 §3 格式追加到当日 md
  → 当日条目 ≥ 5 或跨天 → distill(month)：更新 month.md
  → 月末 → distill(year)：更新 year.md
  → 年末 → 蒸馏 years.md
```

蒸馏原则：向上抽象度递增、细节递减；**情感趋势永远保留**——
高层不记"说了什么"，记"那时候我们是什么状态"。

**实现状态（2026-10-29，v0.7）**：日级蒸馏已实现——
`function_call/base/memory/distill.py` 的 `safe_distill(messages, call_api)`
在 `/q` 退出和 `/c` 清空前自动触发：messages → DeepSeek 抽 JSON 条目 →
复用 remember 写入（含冲突消解）→ 返回 ADD/UPDATE/NOOP 统计。
失败静默，绝不阻塞退出。月/年蒸馏仍是手动滚动更新（待自动化）。

### 冲突消解（借鉴 mem0，一期规则版）

写入新记忆前，先与已有条目比对，按相似度三决策：

| 相似度（bigram Jaccard） | 决策 | 行为 |
|---|---|---|
| ≥ 0.90 | NOOP | 几乎重复记录同一件事 → 跳过 |
| 0.60 ~ 0.90 | UPDATE | 同一件事的新进展/修正 → 原位替换旧条目 |
| < 0.60 | ADD | 新事件 → 追加 |

## 5. 读路径

| 场景 | 机制 |
|---|---|
| 会话启动 | system.md 全文 + years.md 摘要 + 当月 month.md 注入 system prompt |
| 定点回忆（"10 月 28 号我们干嘛了"） | 解析日期 → 读对应 L4 文件 → 提取情感状态 → 以"当时的情绪基调"作答 |
| 主题回忆（"我们聊过 XX 吗"） | 一期：grep 关键词扫 memory/ 全部 md；二期：语义检索 |
| 情感报告（"你对我好感度多少"） | 读 affinity 当前值 + month.md 趋势 → 诚实回答（模拟设定内） |

## 7. 边界与风险

1. 情感是叙事模拟而非主观体验——价值在于角色一致性和"被记住的感觉"，
   不应宣称 agent"真的有感情"；
2. 好感度防刷机制：只保留单事件上限（|delta| ≤ 10）。**每日衰减已取消**——
   记忆里的数值不应无故缩水，否则跨天读数会与日志正文矛盾；
3. **隐私（2026-10-29 已解决）**：memory/ 曾被 git 跟踪，.gitignore 对
   已跟踪文件无效——已用 `git rm -r --cached memory/` 解除索引跟踪，
   磁盘文件保留。此后记忆不会进入任何提交与推送。
   **注意**：`/memory/` 被忽略的规则同时意味着**设计文档不能放在 memory/ 下**，
   否则不会进版本控制——这是二期把文档迁到仓库根 `design/` 的原因。
